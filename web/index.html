How the Repository Code Works Under the Hood

Engineering architecture: strict separation of deterministic code rules and semantic LLM judgment.

src/ad_copy_grader/rules.py Rules D01–D11

Deterministic Engine (D01–D11)

LLMs notoriously miscount characters due to BPE tokenization. Exact hard limits (30 chars per headline D04, 90 per description D05, 15 per path D06) are enforced 100% by pure Python functions with Unicode NFC normalization. Also handles HTTPS validation (D07), duplicates (D08), forbidden exclamation marks (D09), ALL CAPS (D10), and primary service presence (D11).

Latency: <1ms | Cost: $0.00 | Precision: 100%
src/ad_copy_grader/prompt.py Rules A01–A03

Bilingual LLM Audit & Self-Correction

Semantic rules evaluate unverified pricing vs. LP context (A01), missing CTA in descriptions (A02), and clinical/financial guarantees (A03). Uses native Portuguese (PROMPT_PT) and English (PROMPT_EN) system prompts with <ad_payload> XML fencing against prompt injection, parsed by Pydantic with 1 automatic self-correction retry on malformed outputs.

XML Fencing | JSON Schema | 1 Auto-Retry
src/ad_copy_grader/pipeline.py Authority Filter

Server Code Authority Filter

The server never blindly trusts LLM outputs. filter_llm_issues() acts as an automated boundary: strips any deterministic D* rule hallucinated by the model, drops out-of-bounds asset index hallucination, and suppresses A01 false positives whenever the flagged price or offer actually exists in lp_context (as proven in Scenario 3).

filter_llm_issues() | Zero Hallucinated D-Rules
src/ad_copy_grader/rewrite.py CI Quality Ratchet

Validated Rewrites & 3-Column Evals

validate_suggestions() re-audits every LLM rewrite against rules D04/D05/D08/D09/D10; non-compliant rewrites are discarded before reaching the user. Validated with a 3-column Promptfoo evaluation suite (raw vs. pipeline vs. degraded) and CI gates: ruff, mypy --strict, pytest (99.1% coverage), Semgrep OWASP Top 10, and CodeQL.

3-Column Evals | 99.1% Coverage | CodeQL SAST
